Overview

The blog is finished files. nginx serves them; there is no PHP, no database, no container and no login for visitors. Two repositories belong to it:

RepositoryContents
www_hugo (public)The server: playbook and roles
www_hugo_content (private)The site: posts, images, theme, build and deploy

Publishing a post

Posts are Markdown files in site/content/<language>/. Publishing needs neither Ansible nor root. The deploy key can only upload and switch. The last five releases stay on the server, and a rollback takes a second.

# In the content repo
tools/build.sh                 # Hugo + search index into public/
tools/deploy.sh <host>         # upload, then switch atomically
tools/deploy.sh <host> 10022 status
tools/deploy.sh <host> 10022 rollback

Running the playbook

Every real run starts with a check run, one host at a time. Afterwards the drift check must be clean.

# Always first, one host at a time
ansible-playbook blog.yml --limit <host> --check --diff --vault-password-file .vault_pass
# Then for real
ansible-playbook blog.yml --limit <host> --vault-password-file .vault_pass
# Afterwards this must report NO DRIFT
scripts/check-drift.sh blog.yml <host> --vault-password-file .vault_pass

After a run with --tags, also refresh the baselines, or AIDE and rkhunter will mail about the changed files at night:

ansible-playbook blog.yml --limit <host> --tags blog_web --vault-password-file .vault_pass
ansible-playbook blog.yml --limit <host> --tags common_rkhunter,common_aide_refresh --vault-password-file .vault_pass

Updates

dnf-automatic installs security updates at night; nginx comes from the nginx.org mainline repository. Order of the night: AIDE 00:00, updates 01:00–02:00, reboot if needed 03:30, service restarts 03:45, AIDE baseline 04:00. Pinned versions are in inventory/group_vars/all/versions.yml. The common_version_check report shows what is newer.

TLS

certbot obtains certificates through HTTP-01, renews them 30 days before expiry and then reloads nginx. Monit warns when a certificate has fewer than 21 days left or is still self-signed. On a host without matching DNS, blog_web_acme_enabled: false keeps the self-signed certificate.

The domain is on the HSTS preload list. Browsers therefore do not let anyone click past a certificate warning, and clearing browser data does not help. An expired or self-signed certificate means nobody reaches the site. In an emergency, activate a saved certificate that is still valid:

ln -sfn /etc/nginx/tls/<saved>.crt /etc/nginx/tls/current.crt
ln -sfn /etc/nginx/tls/<saved>.key /etc/nginx/tls/current.key
restorecon /etc/nginx/tls/*; nginx -t && systemctl reload nginx

To view a test machine under the real name you need a separate browser profile, in Firefox with network.stricttransportsecurity.preloadlist=false.

HTTP/3

HTTP/3 needs nginx mainline with quic_bpf on. Without it, connections hang after a reload. blog_web_http3: false switches it off in one place, including the firewall rule. To check:

curl --http3-only -sI https://<host>/ | head -1
ps -eo args | grep 'shutting down'     # must be empty about 30 s after a reload
ps -eZ | grep nginx                    # httpd_t
systemctl show nginx -p AmbientCapabilities -p CapabilityBoundingSet

Firewall and bans

Open are 80 and 443 (TCP), 443 (UDP) and SSH on 10022. The host routes nothing, and nginx may not call anything except Grafana on loopback. Each fail2ban jail has its own nftables set pair.

fail2ban-client status
fail2ban-client status nginx-bad-paths
nft list set inet filter f2b_bad_paths4
fail2ban-client set nginx-bad-paths unbanip <address>

Never request forbidden paths from your own machine: two hits ban the address for 24 hours.

Monitoring

Grafana is at /grafana/, from the country list only. Alerts arrive by mail from Grafana and from Monit. Loki keeps logs for 14 days, and access logs stay on disk for 14 days. Visitor numbers exist only as daily totals in /var/lib/visitor-stats/.

Backup

A backup machine pulls the releases, certificates, visitor numbers and SSH host keys every night and versions them with rdiff-backup. Monit warns when the last backup is older than three days. The posts are also in Git. An aborted run leaves no last-success stamp, and rdiff-backup then refuses to version it. Details and the restore are in scripts/blog-backup/README.md. For an older state always restore site, not site/current: that is only a symlink.

Rebuilding

Fresh AlmaLinux 10, ansible_port: 22, run the playbook. It reboots the server once and continues on port 10022. Then set ansible_port to 10022 and deploy the site. The posts need no backup for this, only the Git repository. Visitor numbers and SSH host keys come from the backup. If the first run aborts after the reboot: fix the error, set ansible_port: 10022 and run again. Afterwards scripts/check-drift.sh blog.yml <host> must show changed=0. A brief SELinux alert from useradd while installing Alloy is known and harmless.

Troubleshooting

A service can be "active" and still run in the wrong SELinux domain. Check ps -eZ after every unit or sandbox change.

systemctl status nginx
nginx -t
journalctl -u nginx -n 50
tail -f /var/log/nginx/error.log
ausearch -m avc -ts recent --input-logs </dev/null
monit summary
