Überblick

Der Blog besteht aus fertigen Dateien. nginx liefert sie aus, es gibt kein PHP, keine Datenbank, keine Container und kein Login für Besucher. Zwei Repositories gehören dazu:

RepositoryInhalt
www_hugo (öffentlich)Der Server: Playbook und Rollen
www_hugo_content (privat)Die Seite: Beiträge, Bilder, Theme, Build und Deploy

Beitrag veröffentlichen

Beiträge sind Markdown-Dateien in site/content/<sprache>/. Veröffentlichen braucht weder Ansible noch Root. Der Deploy-Schlüssel darf nur hochladen und umschalten. Die letzten fünf Fassungen bleiben auf dem Server, ein Rollback dauert eine Sekunde.

# In the content repo
tools/build.sh                 # Hugo + search index into public/
tools/deploy.sh <host>         # upload, then switch atomically
tools/deploy.sh <host> 10022 status
tools/deploy.sh <host> 10022 rollback

Playbook ausführen

Vor jedem echten Lauf kommt der Check-Lauf, immer nur ein Host. Danach muss die Drift-Prüfung sauber sein.

# Always first, one host at a time
ansible-playbook blog.yml --limit <host> --check --diff --vault-password-file .vault_pass
# Then for real
ansible-playbook blog.yml --limit <host> --vault-password-file .vault_pass
# Afterwards this must report NO DRIFT
scripts/check-drift.sh blog.yml <host> --vault-password-file .vault_pass

Nach einem Lauf mit --tags auch die Baselines erneuern, sonst melden AIDE und rkhunter nachts die geänderten Dateien:

ansible-playbook blog.yml --limit <host> --tags blog_web --vault-password-file .vault_pass
ansible-playbook blog.yml --limit <host> --tags common_rkhunter,common_aide_refresh --vault-password-file .vault_pass

Updates

dnf-automatic spielt Sicherheitsupdates nachts ein, nginx kommt aus dem Mainline-Repo von nginx.org. Reihenfolge der Nacht: AIDE 00:00, Updates 01:00–02:00, Neustart bei Bedarf 03:30, Dienste neu starten 03:45, AIDE-Baseline 04:00. Feste Versionen stehen in inventory/group_vars/all/versions.yml. Der Bericht von common_version_check zeigt, was neuer ist.

TLS

certbot holt die Zertifikate über HTTP-01 und erneuert sie 30 Tage vor Ablauf, danach lädt er nginx neu. Monit warnt, wenn ein Zertifikat weniger als 21 Tage gilt oder noch selbst signiert ist. Auf einem Host ohne passenden DNS-Eintrag bleibt es mit blog_web_acme_enabled: false beim selbst signierten Zertifikat.

Die Domain steht auf der HSTS-Preload-Liste. Browser lassen deshalb keine Zertifikatswarnung zum Wegklicken zu, und das Löschen von Browserdaten hilft nicht. Ein abgelaufenes oder selbst signiertes Zertifikat bedeutet: Niemand kommt auf die Seite. Im Notfall ein gesichertes, noch gültiges Zertifikat aktivieren:

ln -sfn /etc/nginx/tls/<saved>.crt /etc/nginx/tls/current.crt
ln -sfn /etc/nginx/tls/<saved>.key /etc/nginx/tls/current.key
restorecon /etc/nginx/tls/*; nginx -t && systemctl reload nginx

Zum Ansehen einer Testmaschine unter dem echten Namen braucht es ein eigenes Browserprofil, in Firefox mit network.stricttransportsecurity.preloadlist=false.

HTTP/3

HTTP/3 braucht nginx Mainline mit quic_bpf on. Ohne das hängen Verbindungen nach einem Reload. Abschalten lässt es sich an einer Stelle mit blog_web_http3: false, das gilt auch für die Firewall-Regel. Prüfen:

curl --http3-only -sI https://<host>/ | head -1
ps -eo args | grep 'shutting down'     # must be empty about 30 s after a reload
ps -eZ | grep nginx                    # httpd_t
systemctl show nginx -p AmbientCapabilities -p CapabilityBoundingSet

Firewall und Sperren

Offen sind 80 und 443 (TCP), 443 (UDP) und SSH auf 10022. Der Host leitet nichts weiter, und nginx darf nichts außer Grafana auf Loopback anrufen. Jede fail2ban-Jail hat ein eigenes nftables-Set-Paar.

fail2ban-client status
fail2ban-client status nginx-bad-paths
nft list set inet filter f2b_bad_paths4
fail2ban-client set nginx-bad-paths unbanip <address>

Nie von einem eigenen Rechner aus verbotene Pfade aufrufen: Zwei Treffer sperren die Adresse für 24 Stunden.

Überwachung

Grafana ist unter /grafana/ erreichbar, nur aus der Länderliste. Alarme kommen per Mail von Grafana und von Monit. Loki hält die Logs 14 Tage, die Zugriffslogs liegen 14 Tage auf der Platte. Besucherzahlen liegen nur als Tagessummen in /var/lib/visitor-stats/.

Sicherung

Eine Backup-Maschine zieht jede Nacht die Fassungen, Zertifikate, Besucherzahlen und SSH-Hostschlüssel und versioniert sie mit rdiff-backup. Monit warnt, wenn die letzte Sicherung älter als drei Tage ist. Die Beiträge liegen zusätzlich in Git. Ein abgebrochener Lauf hinterlässt keinen Stempel last-success, und rdiff-backup versioniert ihn dann nicht. Einzelheiten und der Restore stehen in scripts/blog-backup/README.md. Für einen alten Stand immer site wiederherstellen, nicht site/current: Das ist nur ein Symlink.

Neu aufsetzen

Frisches AlmaLinux 10, ansible_port: 22, Playbook starten. Es startet den Server einmal neu und läuft auf Port 10022 weiter. Danach ansible_port auf 10022 setzen und die Seite deployen. Die Beiträge brauchen dafür keine Sicherung, nur das Git-Repository. Aus der Sicherung kommen Besucherzahlen und SSH-Hostschlüssel. Bricht der erste Lauf nach dem Neustart ab: Fehler beheben, ansible_port: 10022 setzen und erneut starten. Danach muss scripts/check-drift.sh blog.yml <host> changed=0 zeigen. Ein kurzer SELinux-Alarm von useradd beim Installieren von Alloy ist bekannt und harmlos.

Fehlersuche

Ein Dienst kann „active“ sein und trotzdem in der falschen SELinux-Domäne laufen. Nach jeder Änderung an Unit oder Sandbox deshalb ps -eZ prüfen.

systemctl status nginx
nginx -t
journalctl -u nginx -n 50
tail -f /var/log/nginx/error.log
ausearch -m avc -ts recent --input-logs </dev/null
monit summary
